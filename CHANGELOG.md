## [7.1.22] — в разработке

### Вкладка «Изображение»: генерация картинок и правка по референсам (правка 929)

- Новая вкладка в H3-интерфейсе: MiniMax H3 в image-режиме (`p-h3-image`).
  Есть генерация по тексту и правка по картинкам: `image_1` — что правим,
  дальше — до 7 картинок-источников (всего до 8).
- `src/lib/comfy/image-template.ts` — билдер графа: `PH3ImageConditioning` +
  `MiniMaxH3SigmaShift` 1.0/1.0 + `ManualSigmas` + `euler` без CFG +
  `LTXVSeparateAVLatent` → `VAEDecode` → `SaveImage`. Пресеты размеров — из
  официальной таблицы (кратность 32 обязательна): 4 МП для правок, 8 МП для
  текста. Две сетки сигм: 8 шагов (официальная) и 4 шага (для дистиллированной базы).
- LoRA `p-h3-image_lora_bf16` (2 ГБ) кладётся поверх уже скачанной **видео**модели:
  структуры совпадают (50 блоков, все 208 целевых модулей LoRA присутствуют,
  размерности идентичны), поэтому отдельный 21-гигабайтный image-DiT не обязателен.
  Текстовый энкодер и VAE обязаны быть image-ными — видео-энкодер с картинкой
  несовместим (другой `text_connector` и single-frame VAE).
- `POST /api/comfy/image` (прогон через общий VRAM-арбитр и единую очередь) и
  `GET /api/comfy/image-assets` (обзор файлов на диске + подсказка, чего не
  хватает). Три файла добавлены в реестр моделей (`Настройки → Модели`,
  помечены как необязательные): LoRA 1,96 ГБ, image-TE 3,58 ГБ, image-VAE 3,15 ГБ.
- Прогон переживает смену вкладки и перезагрузку (модульный `image-job-store`,
  общая очередь, отмена без «красного» бана), результаты показываются сеткой с
  полноэкранным просмотром и скачиванием.

### Сетка: CSRF-guard, DNS-rebinding, запрет iframe (правка 926)

- Аудит безопасности: ни один из 63 мутирующих API-роутов не проверял источник
  запроса. Вредоносная веб-страница могла послать POST на `http://127.0.0.1:3000`
  (simple-request: preflight не требуется, а роуты парсят тело независимо от
  content-type) — вплоть до `/api/reset/full` (удаление данных) и `/api/config`.
  DNS-rebinding обходил бы и обычную origin-проверку (там Host и Origin «совпадают»).
- Добавлен `src/proxy.ts` (в Next 16 это замена middleware.ts):
  • `Host` — только loopback-имя или IP-литерал (rebinding-домены отсекаются;
    LAN-режим по IP работает, доступ по имени машины — нет, это осознанно);
  • POST/PUT/PATCH/DELETE — Origin обязан совпасть с Host; запросы без Origin
    (curl/локальные тулзы) пропускаются, если Sec-Fetch-Site не cross-site;
  • все ответы: `X-Frame-Options: DENY` + CSP `frame-ancestors 'none'`
    (кликджекинг на «Сброс»/«Удалить»).
- `/api/reset/full` теперь требует в теле `confirm:"RESET"` — вторая линия
  защиты; UI шлёт токен.
- Живые проверки на собранном сервере: GET 200; Host evil.com → 403;
  POST с чужим Origin → 403; POST без Origin c Sec-Fetch-Site: cross-site → 403;
  same-origin POST проходит; reset/full без токена → 400.

### Цепочка обновления: https и sha256 обязательны, перепроверка staging, мьютекс (правка 925)

- `UPDATE_FEED_URL` и ссылка на ассет — только `https://`; фид без sha256-дайджеста
  = ошибка вместо прежней молчаливой деградации до проверки размера.
- При взведении в `armed.json` пишется агрегированный хэш дерева staging
  (`sha256-lines-v1`); `apply_update.ps1` пересчитывает его ДО первой записи и
  прерывает установку при подмене файлов между «взведением» и перезапуском
  (старый armed.json без манифеста — проверка пропускается).
- Алгоритм сверен тестом: JS-версия и PS-версия дают идентичный хэш на фикстуре
  с кириллицей/регистром/скрытыми файлами и на боевом дереве из 506 файлов.
- `prepareApply` однопоточный: автоподготовка после скачивания и ручная кнопка
  раньше могли параллельно раскладывать staging в один каталог.
- Подтверждено аудитом и не менялось: zip-slip закрыт (bsdtar отклоняет `..`),
  транспорт https, backup/rollback, кириллица в путях через -LiteralPath.

### Electron: file: больше не «локальный»; снят ACAO:* (правка 927)

- `isLocalAppUrl` пропускал ЛЮБОЙ `file:` URL как локальный — при XSS окно могло
  перейти на локальный файл с подключённым preload-мостом. Теперь только
  `http://127.0.0.1|localhost|::1`.
- Сняты три заголовка `Access-Control-Allow-Origin: *` у `/api/comfy/file`
  (кросс-доменное чтение галереи не нужно — UI same-origin, приватность контента).
- Аудит Electron подтвердил без изменений: contextIsolation, sandbox, в preload
  нет fs/spawn/general-ipc, внешние ссылки — только https через openExternal.

### Traversal и настройки: migrate, comfy_dir, loras (правка 928)

- `/api/models/migrate`: запрещены корень диска, корни профиля и AppData/
  ProgramData/Windows/Program Files в качестве `sourceDir`. Инструмент ищет
  подпапки models/input/output/data до 3 уровней и ПЕРЕНОСИТ их с удалением
  оригиналов — указание, например, `%LOCALAPPDATA%` вырезало бы чужие данные.
  Папка старой установки внутри профиля — по-прежнему разрешена.
- `/api/config`: `comfy_dir` теперь обязан иметь структуру ComfyUI (`main.py` в
  корне или в `ComfyUI\`), а не просто «существующая папка»: из него выводятся
  путь `python.exe` для спавна и roots галерей.
- `/api/loras`: имя LoRA — только плоское имя файла (basename); `getFileSize`
  тоже с basename — раньше `../../…` давал орáкул существования/размера файлов
  вне папки loras.
- Сознательно без изменений: extra-paths (фича «своих папок», после 926 только
  same-origin), symlink/realpath-харденинг (нет API для закладки симлинков),
  bonsai/stt папки (данные/аргументы, исполняемый файл выводится из comfy_dir).

## [7.1.20] — 2026-11-11

### Рефайн «Частями»: текст-описание уходит всем окнам, если ролик одноплановый (правка 923)

- После правки 921 стык в «Частями» 3 с стал мягким, но остался виден
  (юзер: «с 4 секунды плавно до 4.2»). Замеры по новому рендеру
  (`refine_00005`, 260 кадров, 5 окон): отличие результата от исходника
  шагообразно растёт ровно на швах окон — на кадре 107 (шов окон 2→3) MAE
  прыгает 5.77 → 6.38, у соседних кадров шаги по 0.2; сразу после шва
  картинка «дышит»: межкадровая разница 2.96 там, где у исходника 0.87.
- Причина: сюжетный промпт (правка 315) уходил только окну 0, окна 1+
  получали лишь якорные подписи референсов. Для одного плана это значит,
  что все окна после первого рефинятся без текстового гида и дают другой
  рисунок деталей, чем окно 0, - отсюда мягкая смена «рисунка» на каждом шве.
- Теперь промпт уходит ВСЕМ окнам, если текст описывает один план. Для
  многосценных промптов (две и более метки `[Shot N]` / `[Scene N]` /
  `[Сцена N]` / `[Кадр N]`) сохраняется прежняя схема «только окну 0»: там
  описание чужих планов окно путало (наблюдение правки 315).
- Проверки: `tsc --noEmit` - 0; `check-comfy-sync` - 73 пункта OK; разбор
  признака multiScenePrompt на четырёх текстах (одноплановый meta-промпт,
  два плана, дефолтный enhance, русские метки) - классификация верная.

### Настройки: правка пути в «Своих папках моделей» не теряет фокус (правка 922)

- В списке «Свои папки моделей» при ручном исправлении пути в строке каждое
  нажатие клавиши уводило фокус из поля в окно настроек, и дальше поле не
  реагировало на клавиатуру, пока по нему не кликнешь заново.
- Причина: React-`key` строки списка собирался из её же пути
  (`key={`${e.path}|${e.category}`}`). Правка меняет путь → меняется `key` →
  React размонтирует старую строку и монтирует новую, `<input>` пересоздаётся
  и остаётся без фокуса (Radix `FocusScope` возвращает фокус на контейнер
  диалога). Поэтому «следующие нажатия не работали» — текст шёл уже не в поле.
- Теперь у строк есть стабильный внутренний `uid` (счётчик уровня модуля), он и
  используется как `key`; изменение пути и категории на него не влияет. В
  `save()` как раньше уходят только `path` + `category`.
- Проверено вживую в Electron на собранной 7.1.19: до фикса после первого
  символа `document.activeElement` — контейнер диалога, DOM-узел поля заменён,
  значение больше не меняется; после фикса фокус остаётся в поле и путь
  набирается целиком.

### Рефайн «Частями»: стык окон больше не попадает в кроссфейд сегментов декода (правка 921)

- На коротких роликах (~6 с) с окном **3 с** в середине видео был виден стык,
  при окне 5 с его не было. Причина: полный латент режется на сегменты декода
  по 25 токенов, и на каждом стыке сегментов 17 кадров кроссфейдятся (правка
  820). В 3 с стыки окон идут каждые 10 токенов, поэтому первый же стык
  (токен 22 ≈ кадр 73 — ровно середина 6-секундного ролика) попадал внутрь
  зоны кроссфейда `[20, 25)`: смешивались два независимых декода, между
  которыми лежала смена содержимого, — шов «размазывался» на 0,7 с и
  читался глазом. При 5 с на таком ролике окно одно, стыка нет вовсе.
- Теперь границы сегментов планируются с учётом стыков окон: граница
  сдвигается на ближайшую свободную, кратно 5 токенам (фаза FPT сохраняется,
  кадровая арифметика сегментов остаётся точной), предпочтительно назад —
  так зона кроссфейда целиком лежит до стыка, а сам стык попадает в тело
  следующего сегмента. Хвост короче головы перекрытия сливается с предыдущим
  сегментом.
- Для 6 с / 3 с сегменты теперь `20 + 22` токена вместо `25 + 17`: кроссфейд
  на кадрах 51–67, стык окна на кадре 73 — вне зоны смешения. Для 260-кадрового
  теста с 5 с границы не изменились (`25, 50, 70, 77`) — вывод 5 с остаётся
  прежним, регресса нет.
- Проверки: `tsc --noEmit` — 0; `check-comfy-sync` — 73 пункта OK; симуляция
  планировщика на 3423 комбинациях (3/5/8 с × 60…1200 кадров) — суммарная
  длительность кадров точная, ни один стык окна не попадает в зону кроссфейда.

### Установка: старый Visual C++ redist ставится попутно (правка 920)

- На ноутбуке юзера `import torch` падал с `OSError: [WinError 1114] Сбой
  инициализации DLL. Error loading ...\torch\lib\c10.dll or one of its
  dependencies`, и установка завершалась тремя ошибками шага 9 (torch, часть
  библиотек, ComfyUI не поднялся за 180 с) — хотя колёса torch скачивались с
  верным sha256. Причина: старый Microsoft Visual C++ 2015-2022 x64 Redistributable
  в System32 (`msvcp140.dll` / `vcruntime140*.dll`) — `c10.dll` линкуется с ними.
  Ручное обновление redist вылечило установку полностью.
- Шаг 1 теперь проверяет версию `msvcp140.dll` / `vcruntime140*.dll` и, если
  файла нет или версия старше **14.40**, тихо скачивает и ставит
  `vc_redist.x64.exe` (aka.ms/vs/17/release), затем перечитывает версию.
- Ошибка redist установку не прерывает: при неудаче — предупреждение с прямой
  ссылкой на скачивание и совет запустить от администратора. Коды 1638 («уже
  стоит новее») и 3010 («нужна перезагрузка») обрабатываются отдельно.
- Скачанный установщик кэшируется в `.install-cache\vc_redist.x64.exe` —
  повторная установка не качает заново.

### Аудио: беззвучное видео в ComfyUI 0.44 (правка 917)

- **Правка 916 не лечила проблему до конца.** В 0.44 ядро обходит все
  подключённые выходы ноды через `comfy.model_patcher.PromptModelTracker.add()`,
  который зовёт `.values()` на любом `Mapping`. Выход AUDIO у `VHS_LoadVideo` —
  ленивый `LazyAudioMap`: его трогают **на ноде-загрузчике**, и на беззвучном
  ролике ffmpeg (`-f f32le -`, «Output file does not contain any stream») бросает
  `VHS failed to extract audio` — задание падало раньше, чем до звука доходил
  `MiniMaxH3AudioOrSilent`. В 0.33 этого обхода выходов не было, поэтому раньше
  работало.
- **Патч VideoHelperSuite** (`install/vhs-patches/videohelpersuite/utils.py`):
  `LazyAudioMap` при сбое извлечения кэширует пустой маппинг вместо исключения.
  Дальше всё штатно: guard подставляет тишину, `_audio_has_samples` даёт False,
  `VHS_VideoCombine` сам пропускает мукс (у него свой try/except).
- Патч применяется на шаге 6 установки **после** распаковки нод (иначе архив
  ноды затирает пропатченный файл) и при повторном запуске `install.bat`.
- Проверено на python_embeded тестовой установки: обход выходов не падает,
  `get('waveform')` → None, `len()/iter()` безопасны, VideoCombine не муксит;
  регресс — видео со звуком по-прежнему отдаёт реальную дорожку, ffmpeg не
  вызывается повторно. Синтетический беззвучный mp4 воспроизводит исходный

### Ассистент: замена референсов посреди чата (правка 906)

- **Ассистент больше не может принять старое описание за новый референс.**
  Описания референсов кэшируются по содержимому файла, но у кэша есть резервный
  индекс «имя файла → последнее описание» для случаев, когда дайджест не удался
  (нет mmproj, таймаут, LLM занят, исчерпан 7-минутный бюджет). Индекс не
  проверял содержимое: после замены рефа с тем же именем (типично — после
  «чистки input», смены папки бэкенда или перезалива файла) модель получала
  описание **старого** файла, а сырое изображение при этом не прикреплялось —
  то есть не могла увидеть новое. Теперь в индексе хранится отпечаток
  содержимого (размер + хэш), и описание принимается только при совпадении;
  устаревшее отбрасывается, и маршрут уходит в честный путь «файл приложен
  напрямую» или «не вижу, mmproj нет».
- **Модель получает явное предупреждение «РЕФЕРЕНСЫ ИЗМЕНИЛИСЬ».** Метка
  `<Picture N>` — это позиция в списке, а не идентификатор файла: после замены
  рефа (UI делает «убрать» + добавить, новый файл встаёт в конец) тот же номер
  начинает означать ДРУГОЙ файл, а в истории чата остаются реплики ассистента
  про прежний. Чат теперь хранит отпечаток набора, который модель реально
  видела, и при расхождении в системный промпт добавляется блок с диффом
  (что изменено / появилось / убрано) и правилом: не переносить описания из
  прошлых реплик и уточнять, о каком референсе речь, если пользователь
  ссылается на «второй» по смыслу старого файла.
- **Системный промпт и payload собираются из ОДНОГО снимка референсов.**
  Раньше промпт пересобирал список сам уже после `await fetch('/api/config')`
  (до 5 с) — если пользователь в это окно менял рефы, промпт перечислял новый
  набор, а файлы прикреплялись старые (тот же класс бага, что закрывала
  правка 823).
- **Отпечаток больших файлов (видео) стал надёжнее.** Раньше хэшировались
  только начало и конец файла: два разных ролика одного размера с совпадающими
  краями получали ОДИН ключ кэша, и модель описывала чужое видео. Теперь 4
  пробы по диагонали файла (начало, 1/3, 2/3, конец) со смещениями в хэше.

- **Индекс описаний ограничен 400 записями** (раньше рос бесконечно — по
  записи на каждое когда-либо описанное имя файла).

- **Отдельная sigma-лестница Pass 2 при выключенном 3D-апскейлере.** Штатная

  латента от 3D-апскейлера это рассчитано, но bislerp-растянутый латент
  (правка 811) вне обучающего распределения — за 3 шага шум не разглаживался
  и оставался как «паутинка/перхоть». При обходе 3D-апскейлера теперь
  используется своя лестница `BYPASS_SIGMA_VARIANTS`. Эксперименты: v1
  (старт 0.50) и v2 (0.70) дали сетку латентных патчей — мало перерисовки;
  итоговая v3 — наоборот горячее штатной: старты 0.95–0.98 (но <1.0, иначе
  вклад латента pass 1 обнуляется). Все варианты 3–7 step; в main-цепочке
  и в extend-клипах.

  логи, а также очищает `localStorage`/`sessionStorage`. Настройки, LoRA и
  `config.ini` возвращаются к заводским. Модели и `custom_nodes` не
  трогаются. После сброса программа перезапускается — её можно передавать
  другому человеку.

  (low-res → latent upscale → high-res), H.264 / 24 fps.

  секундам). Режим Draft — быстрая однопроходная генерация.

- `scripts/build.mjs` — production-сборка с хипом Node 8 ГБ

- `scripts/release.mjs` — полный цикл релиза
  (clean → typecheck → build → prune → verify) с проверкой комплектности сборки.

### Face Refine (правка 722)

- **Новая вкладка «Face Refine»** — перерисовка мелких лиц в готовом ролике.
  H3 плохо рисует лицо, когда голова занимает малую долю кадра, и это свойство
  кадра, а не разрешения (на 720p и выше проблема остаётся). Нода находит лицо
  покадрово, кропит его так, чтобы оно занимало ~40 % холста, перегенерирует
  крупно с низким denoise и вклеивает обратно **только область лица**
  (feather + колор-матч). Остальной кадр остаётся исходным.
  Используется набор нод `ComfyUI-H3-FaceRefine` (Carasibana, MIT) — он уже
  стоял в `custom_nodes/`, но был нерабочим: не было детектора и
  python-пакетов. Установлены `ultralytics`, `scenedetect`, `insightface`
  (torch не тронут) и скачаны `face_yolov8m.pt` + `person_yolov8m-seg.pt`.
- **Кого именно перерисовывать** — три способа:
  * правило + номер в рейтинге (`Самое крупное лицо`, `Ближе к центру кадра`,
    `Самое левое/правое/верхнее/нижнее`, `Самое мелкое`, `Самое уверенное`);
  * **клик по лицу в кадре исходника** (правка 723) — окно с превью ролика,
    прокруткой по кадрам и точкой на нужном лице: трекер берёт ближайшее к
    точке лицо и ведёт этого человека через весь ролик. Правила видят только
    геометрию кадра, поэтому в толпе и на общих планах выбор «залипал» на одном
    и том же лице, а точка задаёт цель напрямую. Координаты считаются в
    пикселях самого видео, номер кадра — по fps из `ffprobe` (элемент `<video>`
    кадров не отдаёт), так что клик попадает в тот кадр, на котором сделан.
    **Точка главнее референс-фото:** при подключённом `identity_reference` нода
    вообще не смотрит на X/Y (в отчёте — «ignored - identity_reference
    decides») и ведёт того, кто совпал с фото, — поэтому, пока лицо выбрано
    кликом, фото в воркфлоу не подаётся, а в метаданных остаётся пометка
    `identity_reference_ignored`;
  * **референс-фото конкретного человека** — трекер сопоставляет лица по
    эмбеддингу (insightface, `buffalo_l` скачивается сам при первом запуске) и
    ведёт этого человека через весь ролик, даже если нумерация лиц сбилась.
- **Промпт и референсы берутся из сайдкара исходника** — Face Refine должен
  перерисовывать лицо в той же сцене, поэтому сцена и персонажи те же.
  Свой промпт можно задать вручную.
- Параметры под наше железо: канва 512 (дешевле 768 в 2.25× по latent-токенам),
  4 шага (наша модель 4-шаговая), базовый denoise 0.35. Денойз из SDXL-семейства
  не переносится: H3 — flow matching со сдвигом 12, denoise 0.25 → эффективная
  sigma 0.800 (кадр переписывается целиком).
- **Денойз масштабируется по размеру лица** в кадре: мелкие лица получают
  полную силу, крупные — множитель 0.35 (у них уже есть детали).
- **Живое превью генерации** — как на вкладках «Генерация», «Refine» и
  «Tile Upscale»: KJ-нода `ModelPreviewOverrideKJ` в model-цепочке шлёт кадр на
  каждом шаге сэмплинга, статус внизу показывает его через
  `/api/comfy/preview`. Стандартные превью в этой сборке отключены
  (`--preview-method NoPreviews`), без KJ-ноды окно оставалось пустым.
- **«Далёкие планы» — детектор человека** (`fallback_detector`). На кадрах, где
  лица не видно (человек спиной, в капюшоне), трекер берёт бокс
  `person_yolov8m-seg` и считает головой его верх — это точнее, чем
  интерполировать между соседними найденными лицами. Папку детекторов студия
  теперь регистрирует сама (`extra_model_paths.yaml` → категория `ultralytics`
  → `models/ultralytics`), иначе нода видела только дефолтный
  `face_yolov8m.pt`; значения комбо резолвятся по `/object_info`, чтобы имена с
  подпапкой (`bbox/face_yolov8m.pt`) совпадали со списком бэкенда.
- Результат — обычное видео в общей галерее, с бейджем «Face Refine»
  (салатовая метка; сама вкладка — жёлтая) и полными метаданными
  (canvas/denoise/steps/правило выбора/сид/источник/время).

### Известные ограничения

- Требуется NVIDIA GPU (12+ ГБ VRAM рекомендуется, минимум 8 ГБ) и
  драйвер CUDA 12.x.
- Live-режим (real-time / HLS) в студию **не входит**: это отдельный
  инструмент (свой HLS-сервер и плеер), а не обработка файла. Вкладка
  «Upscale» работает только с готовыми видеофайлами.
- ESLint в проекте не используется; проверка качества — `npm run typecheck`.
