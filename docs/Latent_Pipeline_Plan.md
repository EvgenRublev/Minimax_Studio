# План: латент-пайплайн «драфт → рефайн»

**Цель:** убрать двойную потерю качества (h264 + VAE roundtrip) на пути
«драфт → рефайн»: рефайн должен стартовать с первозданного латента,
а не из mp4. Побочно — ускорение рефайна (можно пропустить Pass 1).

## 1. Нода SaveLatent/LoadLatent (ComfyUI)

- Своя мини-нода (~40 строк) в `ComfyUI/custom_nodes/` — без внешних
  зависимостей. Альтернатива: пакет comfyui-tooling-nodes (хуже — чужой
  формат AV-латента не гарантирован).
- Формат: один `.safetensors` на клип, внутри два тензора:
  `video_samples`, `audio_samples` (AV-латент целиком) + JSON-шапка
  (frames, genW, genH, fps=24, версия VAE).
- Сохранение в `ComfyUI/output/latents/Minimax_Studio_XXXXX.latent`.
- LoadLatent — зеркальная нода: читает файл, возвращает AV-латент.

## 2. Сохранение в шаблонах (src/lib/comfy/minimax-h3-template.ts)

- Режимы `draft` и `full`: после сэмплера добавить SaveLatent:
  - **full**: сохраняем ФИНАЛЬНЫЙ латент (после Pass 2);
  - опционально позже: латент Pass 1 (для рефайна «с нуля в большом
    разрешении» без повторного Pass 1).
- Имя файла = filename_prefix результата (связка 1:1 с mp4).
- Метаданные (`data/*.json` сайдкары / genParamsMap): поле
  `latentFile: "latents/Minimax_Studio_XXXXX.latent"`.

## 3. Ветка загрузки в рефайне (src/lib/comfy/refine-template.ts)

- Если у исходного видео в мете есть `latentFile` — строим воркфлоу с
  `LoadLatent` ВМЕСТО `VHS_LoadVideo → VAEEncode`:
  - пропускаем загрузку mp4 и encode целиком;
  - дальше пайп без изменений: 3D-апскейл → части → маски → сэмплеры.
- Fallback: латента нет / файл удалён / несовпадение VAE — текущий путь
  через mp4 (ничего не ломается для старых файлов и чужих видео).
- Валидация при импорте в рефайн: показать бейдж «латент ✓» на карточке
  источника (refine-view), чтобы было видно, пойдёт ли lossless-путь.

## 4. UI/галерея

- `.latent` НЕ показывать как отдельный элемент галереи — это приставка
  к mp4 (фильтр по расширению в /api/comfy/files уже есть, проверить).
- В диалоге метаданных показывать наличие латента.

## 5. Хозяйство

- Авто-чистка: удалять `.latent` вместе с mp4; кнопка «очистить латенты»
  (или лимит по возрасту, например старше 7 дней).
- Оценка места: драфт 0.2 Мп ≈ 1–2 МБ; full 0.7 Мп ≈ 5–10 МБ — приемлемо.

## 6. Риски и границы

- Латент валиден только с тем же VAE (у нас один video VAE — ок; при
  смене VAE старые латенты инвалидируются — версия VAE в шапке файла).
- Рефайн из латента меняет геометрию только на входе; маски/части/швы
  не трогаем — регрессий в склейке быть не должно.
- Extend-режим в первой итерации не трогаем (там своя латент-цепочка);
  при желании — отдельным этапом.

## Порядок работ

1. Нода Save/LoadLatent + ручной тест в ComfyUI.
2. Шаблон генерации: сохранение + мета.
3. Шаблон рефайна: ветка LoadLatent + fallback.
4. UI: бейдж «латент ✓», скрытие из галереи, чистка.
5. Прод-сборка + живой тест: драфт → рефайн lossless vs mp4-путь.

## Статус реализации (10.10.2026)

- [x] **Нода** (правка 372): `custom_nodes/minimax_studio_av_latent/` —
  `MiniMaxStudioSaveAVLatent` / `MiniMaxStudioLoadAVLatent`. Roundtrip
  проверен standalone-скриптом (embedded python): тензоры побитово,
  шапка (fps/vae/version), path-traversal блокируется.
- [x] **Шаблон генерации** (правка 375): нода '46:49' в draft/full (extend —
  нет). Сохраняется тот же выход сэмплера, что идёт в decode. Путь латента
  пишется в сайдкар как `latent_file` из `ui.latents` при финализации меты
  (сервер: pending-meta.ts; клиент: use-video-gen.ts) — связка с mp4 НЕ по
  счётчикам имён (они у нод независимые).
- [x] **Шаблон рефайна** (правка 376; геометрия — 381/382): `RefineParams.sourceLatent` +
  `sourceFrames`. Latent-ветка: LoadAVLatent → [Separate → Upscaler →
  Concat при апскейле] → сэмплер; mp4 грузится только первым кадром
  (frame_load_cap 1) для conditioning-якоря; длина conditioning/превью —
  числом с сервера (сетка 17k+5 от ffprobe-кадров). Roут валидирует:
  не legacy-кусок, цель ≥ канвы латента, `latent_file` в мете, mp4 не менялся
  (кадры/разрешение совпадают с метой), шапка safetensors (версия, VAE +
  размеры из shape: латент × 16 — `src/lib/latent-file.ts`, общий резолвер
  `resolveSourceLatent` в refine-meta.ts). Любой отказ → тихий fallback
  на mp4-путь. Геометрия ветки — от КАКНВЫ ЛАТЕНТА (≥ mp4 из-за кропа
  генерации): у свободного-MП генератора ceil32(mp4) ≠ канва — conditioning
  и затравка обязаны совпадать.
- [x] **UI** (правка 377): бейдж «Латент ✓ — рефайн без потерь» на карточке
  источника (refine-view; `latent_available` в /api/comfy/meta, файл-чек на
  сервере); в диалоге меты путь виден в «Ещё».
- [x] **Хозяйство** (правка 378): `.latent` удаляется вместе с mp4
  (/api/comfy/delete); папка `latents` скрыта из списка папок галереи;
  сами файлы фильтруются расширением (VIDEO/IMAGE_EXTS).
- [ ] **Живой тест**: драфт → рефайн lossless vs mp4-путь (сравнение
  качества/скорости) — требует запуска генерации на GPU.

- [x] **Tile Upscale** (правка 381): `TileUpscaleParams.sourceLatent` —
  MMH3UltimateUpscale получает загруженный латент вместо
  Empty→H3InjectVideoLatent (без h264 + повторного VAE-encode). mp4 грузится
  одним кадром (first_frame) + аудио-дорожкой целиком на mux (аудио-выход
  VHS не режется frame_load_cap — правка 322). Цель — от канвы латента;
  target < канвы → fallback mp4.
- [x] **Refine «Частями»** (правка 382): окна режутся ТОКЕНАМИ загруженного
  латента (LatentCut dim 't') вместо пиксельных срезов + VAEEncode по окну;
  аудио окон — срезы аудио-латента генерации (dim 'x'). Токен-границы =
  кадры сетки 17k+5: у окон с off-grid skip фактический старт съезжает ≤17
  кадров — срезы аудио и стыковочная арифметика (overlap → cutTok) считаются
  от тех же эффективных границ, непрерывность цепочки сохраняется.
  Legacy-кусок (chunkJob/skipFrames/frameCap) и реюз без пробы — mp4-путь.
- [x] **Продление** (правки 383/384 — ❌ ОТКАЧЕНО правкой 417): воркфлоу extend собирает КОМБИНИРОВАННЫЙ
  латент того же таймлайна, что склейка:
  `src[:F−17] ⊕ клип0[от sliceStart] ⊕ клипы i>0[от 22]` — все срезы по
  границам токенов (17 кадр. = 5 ток., 22 = 7, sliceStart на сетке), длины
  совпадают (Trim 9 + Fade 8 = 17). И вывод — по схеме «Частями» (как
  правка 314): комбинированный латент декодируется СЕГМЕНТАМИ по 25 токенов
  (пик VRAM ограничен сегментом) и кодируется h264 ОДИН раз (crf 12).
  Поштучные extclip-файлы и повторное кодирование ffmpeg-склейки
  упразднены; стык «исходник → клип 0» без xfade (обе стороны — один и тот
  же VAE-раундтрип идентичных латентов, скачка характера нет). Клиент после
  джоба вызывает /api/comfy/concat?metaOnly — роут пишет в сайдкар
  ФАКТИЧЕСКИЕ video_length/resolution/duration (ffprobe итога; это же
  условие целостности для резолвера) + latent_file. Продление БЕЗ исходника
  — прежний поштучный путь (extclip-файлы, склейки нет).

Не делаем (границы первой итерации, см. §6): латенты результата рефайна
(refine→refine) и апскейлов (DLSS/RTX/FPS).

- [x] **Сид продления из латента исходника** (правка 385 — ❌ ОТКАЧЕНА правкой 417): если у источника
  продления есть латент (генерация / прошлый extend-combined; клиент шлёт
  имя+подпапку оригинала в output, роут резолвит через общий резолвер и
  ставит канву продления = канве ЛАТЕНТА) — часть исходника комбинированного
  латента режется ТОКЕНАМИ первозданного латента (бит-в-бит, проверено
  численно на реальных файлах: max|diff| = 0 на всей длине шва).
  Токены/аудио-шаги — точно из шапки .latent (срез шва без дрейфа).
  Fallback: латента нет/невалиден/чужое видео — пиксельный путь правки
  383/384 (кодирование полного исходника в графе).
- [x] **Гибридный сид продления** (правка 409 — пиксельный сид остался, комбинированной части больше нет): сид-хвост (preserved-голова
  клипа 0 / motion-контекст модели) снова ВСЕГДА — VAEEncode пикселей
  mp4-хвоста, как до правки 385. Срез первозданного латента как seed давал
  скачок/артефакт на стыке «исходник → клип 0»: продолжение генерировалось
  из OOD-контекста (сгенерированный латент ≠ VAE-encode пикселей, на которых
  обучен ref2v-продленец). Латент исходника используется только для
  комбинированной части (extcf_v/extcf_a) — там срез доказанно точен.
- [x] **Мета combined-файла** (правка 410): finalizePendingMeta для extend с
  исходником пишет ФАКТИЧЕСКИЕ video_length/resolution/duration (ffprobe
  итога), а не плановые кадры клипов — иначе резолвер латента отклонял
  комбинированный латент при следующем продлении (несовпадение с probe mp4).

Если у исходника есть свой первозданный `.latent` — итог собирается из него
(ноль энкодов исходника), иначе один VAE-энкод целиком в графе.
